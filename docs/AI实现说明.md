# 微光写作台 AI 实现说明

## 1. 边界

- 软件不内置本地 AI 模型。
- AI 功能必须由用户配置自己的 OpenAI 兼容 API。
- 项目数据、长期记忆、恢复点和分析报告保存在本机。
- AI 请求直接从本机发送到用户配置的模型服务商，不经过项目自有服务器。
- 不存在静默的后台 AI 调用。

## 2. 请求路径

1. 用户在 AI 设置中填写 Base URL、模型名和 API Key。
2. API Key 使用 Windows DPAPI 加密保存在本机。
3. 用户主动点击生成、体检或提取记忆时，前端组装上下文。
4. Tauri 通过 Rust/WinHTTP 网络桥向用户配置的 `/chat/completions` 发送请求。
5. 流式响应按 SSE 解析。
6. 正文修改不会自动写入。续写、改写等结果都需要用户确认。
7. 改写模式展示原文与生成结果的 Diff，确认后替换生成时捕获的选区。

## 3. 上下文包

普通创作请求包含：

- 当前场景正文
- 当前选区及稳定 `block_id`
- 相邻场景必要片段
- 故事圣经、人物卡和别名
- 相关伏笔
- 当前章节相关时间线
- 作者本次要求和目标长度
- 已确认的长期记忆

候选记忆、已拒绝记忆和未插入正文的 AI 建议不会作为长期事实使用。

`context_pack` 有固定预算：

- 输入目标：8,000 Token
- 输出目标：2,000 Token

实际请求仍受用户所配置模型的上下文窗口限制。

## 4. 自动参考价

- 用户不再手动填写模型单价。
- 软件按模型名称和接口域名匹配内置参考价。
- 参考价可能随服务商调整，最终以服务商账单为准。
- 未知模型不虚构价格，只记录实际 Token。
- 所有模型都可以通过月度 Token 上限控制用量。
- 请求前会做 Token 估算、上限检查和失败阻止。

## 5. 结构化长期记忆

记忆表保存在本机 SQLite：

- 事实
- 事件
- 人物关系
- 地点、物品和组织
- 伏笔
- 角色认知
- 世界规则

每条记忆包含：

- 所属项目
- 来源章节和场景
- 证据 `block_id`
- 原文短引用
- 置信度
- 候选/已确认/已拒绝/已失效状态

AI 只提交候选记忆。作者确认后才进入上下文。候选记忆不会自动改写正文或故事圣经。

## 6. 场景体检

- 使用当前场景和必要设定生成结构化冲突列表。
- 结果包含严重程度、置信度和原文证据。
- 只报告问题，不直接修改正文。

## 7. 全书体检与拆书

- 来源可以是当前项目正文，或用户确认拥有授权的 TXT/Markdown 文件。
- 正文按约 12,000 字符分块。
- 分块先生成编辑笔记，再汇总为最终报告。
- 支持阶段进度与取消。
- 分析不修改作者正文。
- 最终报告保存在本机 SQLite，并可进入完整项目备份。

## 8. 失败与恢复

- 请求失败不写入正文。
- 取消后不产生半成品记忆。
- 应用正文前自动创建场景恢复点。
- 恢复点不使用 Git。
- 完整项目备份包含正文、故事设定、长期记忆、恢复点和分析报告。
